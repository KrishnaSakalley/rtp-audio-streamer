# RTP Audio Streaming Pipeline

[![CI](https://github.com/KrishnaSakalley/rtp-audio-streamer/actions/workflows/ci.yml/badge.svg)](https://github.com/KrishnaSakalley/rtp-audio-streamer/actions/workflows/ci.yml)

A C++17 low-latency audio streamer built from scratch: hand-rolled RTP packetisation
(RFC 3550), two audio codecs (G.711 mu-law, IMA ADPCM), a network impairment simulator,
an adaptive jitter buffer with packet loss concealment, and a lock-free SPSC ring buffer
feeding a threaded, real-time playout clock. No external RTP, DSP, or codec libraries —
the protocol and codec implementations are the entire point of the project.

File-to-file, not a live microphone/speaker: the whole pipeline runs with no sound card
present, and correctness is verifiable with `cmp` rather than judged by ear.

## Architecture

```
WAV in
   | encode (G.711 mu-law / IMA ADPCM / raw PCM)
   | RTP packetize (RFC 3550, 12-byte header)
   | UDP  --> [impair: loss / reorder / jitter / dup] -->
   | adaptive jitter buffer (reorder + packet-loss concealment)
   | lock-free SPSC ring buffer
   | decode --> 20 ms real-time playout clock
WAV out
```

Three binaries: `rtp_sender`, `rtp_receiver`, `impair`. See
[docs/WALKTHROUGH.md](docs/WALKTHROUGH.md) for a full component-by-component writeup —
what each piece does, the algorithm and its spec reference, why this design over the
obvious alternative, and the failure mode if it's wrong.

## Build

Requires a C++17 compiler (GCC or Clang), CMake >= 3.16, and POSIX threads (Linux/WSL2 —
the project uses `clock_nanosleep` and POSIX sockets directly, no portability shims).

```bash
cmake -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build -j
ctest --test-dir build --output-on-failure
```

## Run

```bash
# Direct loopback, raw PCM
./build/rtp_receiver output.wav --port 5004 --idle-timeout-ms 800 &
./build/rtp_sender input.wav --host 127.0.0.1 --port 5004 --codec pcm

# Through the impairment simulator, with G.711 mu-law and packet loss concealment
./build/rtp_receiver output.wav --port 5006 --idle-timeout-ms 800 &
./build/impair --listen 5004 --forward 5006 --loss 0.05 --reorder 0.02 --jitter 30 &
./build/rtp_sender input.wav --host 127.0.0.1 --port 5004 --codec ulaw

# Same, with PLC disabled for comparison (lost frames become silence, not a faded repeat)
./build/rtp_receiver output.wav --port 5006 --idle-timeout-ms 800 --no-plc &
```

`--codec {pcm|ulaw|adpcm}` selects the codec on `rtp_sender`; `rtp_receiver` decodes
based on the RTP payload type in each packet, so it needs no matching flag. Generate a
synthetic test tone with `./build/gen_test_tone out.wav <duration_s> <freq_hz>`.

## Design summary

- **Fixed format everywhere:** 8 kHz, mono, 16-bit PCM, 20 ms frames = exactly 160
  samples, defined once and never inlined ([audio_format.hpp](include/rtp/audio_format.hpp)).
- **No heap allocation on the audio path after startup, no exceptions on it either** —
  file I/O and one-time setup are the exception to both rules, not the per-packet path.
- **Every wire-format byte is packed and parsed by hand** — RTP headers with
  `htons`/`htonl`, never a `memcpy`'d struct (padding and host endianness would corrupt
  the wire format silently).
- **Real bugs, found and fixed, not hidden:** a nondeterministic reordering bug in the
  impairment tool's thread-per-packet forwarding, and a jitter buffer bug where playout
  could race arbitrarily far ahead of what any packet had actually proven exists. Both
  are documented with root cause and fix in [docs/NOTES.md](docs/NOTES.md), and both
  have regression tests.
- **Verified, not assumed:** a 10M-item two-thread stress test for the lock-free ring
  buffer, a ThreadSanitizer run of the full threaded pipeline, and a 60-second
  zero-underrun run — see [docs/NOTES.md](docs/NOTES.md) for the phase-by-phase build
  log.
